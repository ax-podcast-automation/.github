# 둥실둥실 — AX Podcast Automation

SW 쇼케이스 출품작. 한국어 뉴스 기사를 **앵커–리포터 대담 형식의 방송용 팟캐스트**로 자동 변환한다.

뉴스→오디오 변환이 아니라 **다단계 검증 시스템**이다. 기사를 읽고 대본을 쓰는 건
LLM 몇 번 호출하면 된다. 실제 문제는 **"그 대본이 원문에 없는 걸 지어내지 않았다는 걸
어떻게 증명하느냐"** 이고, 학술적 기여점도 거기 있다 — LLM Judge의 판정이 사람
평가자와 얼마나 일치하는지를 측정하는 캘리브레이션.

> **검증으로 잡기보다 생성을 제약한다.**
>
> 검증이 어려우면 검증기를 똑똑하게 만들 게 아니라 생성을 제약한다.
> 변환이 일어나지 않으면 변환을 검증할 일도 없다.

## 레포

| | 내용 | 스택 |
|---|---|---|
| **[ai](../../ai)** | 파이프라인 · 계약 · Judge · 캘리브레이션. **여기가 본체다** | Python |
| [backend](../../backend) | HTTP 레이어. 의도적으로 얇다 | FastAPI · SQLite |
| [frontend](../../frontend) | 방송국용 화면 | Vite · React |

의존은 한 방향으로만 흐른다.

```
frontend  ──HTTP──▶  backend  ──pip──▶  ai
    └───────── contracts/*.schema.json ─────────┘
```

**파이프라인은 웹을 모른다.** 캘리브레이션 숫자는 웹 없이 수백 번 돌려야 나오는데,
그때마다 서버를 띄워야 하면 실험 속도가 죽고 발표 숫자가 안 나온다. 레포를 가른
것은 이 경계를 약속이 아니라 구조로 만들기 위해서다.

계약의 단일 출처는 `ai` 의 pydantic 모델이고, JSON Schema는 거기서
생성해 아래 두 레포로 내려간다. 손으로 쓴 타입이 서버 응답과 어긋날 자리를 없앤다.

## 파이프라인

```
P0  자료 정제            붙여넣은 기사 → 헤더·오염 제거 → 문장 분할
P1a 문장 중요도          BERT salience
P1b 사실 추출            팩트카드 (FACT/OPINION × 인용 여부) + 날짜 절대화
P2  아웃라인             a 코드 필터 / b LLM 생성 / c 커버리지 검증
P3  대본 생성            팩트카드만 보고 쓴다
J1  사실성 Judge         ← 기사 단위 하드 게이트
P4  병합 · 브릿지 · 조립
J2  통합 검증            ← 브릿지 하드 게이트
P5  TTS 정규화           → Qwen3-TTS 음성 복제
```

**Judge는 둘이고 나머지는 코드다.**
